Desktop Applications (lila desktop)

A Lila app is a normal ASGI application, so it can also run inside a native window: the server starts on a local port and the OS webview (WebView2/WebKit) renders it. Measured footprint for the Python side: import lila ≈ 19 MB RSS and a full App ≈ 42 MB; the window itself uses the webview already installed in the operating system instead of bundling a browser.

1. Running in Desktop Mode

lila desktop dev loads .env, finds a free port, starts Uvicorn in a daemon thread and opens a native window. It binds only to 127.0.0.1, allows a single instance and gates the session with a per-run token that is exchanged for an HttpOnly cookie on the first navigation: 

# Starts Uvicorn in a daemon thread and opens a native window
lila desktop dev

# Custom options:
lila desktop dev --title "My Desktop App" --width 1280 --height 850
💡 Dual Window Engine:
  • Preferred (pywebview): Uses Microsoft WebView2 on Windows, WebKit on macOS, and WebKitGTK on Linux. Install with: pip install "lila-framework[desktop]"
  • Fallback: if pywebview is not installed, Lila detects Edge, Chrome or Brave and launches an isolated standalone --app window; if none is found it opens the default browser.

2. Compiling Standalone Executables (.exe / Binary)

lila desktop build writes a temporary bootstrap that imports main statically (so PyInstaller can see your code), then bundles main, app and Lila's data files (--collect-all lila), plus public/ and resources/ when they exist. Output goes to dist/<name>. 

# Install packaging dependencies:
pip install pyinstaller pywebview
# or: pip install "lila-framework[desktop]"

# Build a single-file executable:
lila desktop build --name "InvoiceManager" --onefile --windowed

# Onedir build (faster startup, easier to inspect):
lila desktop build --name "InvoiceManager" --onedir

# The compiled binary is ready in dist/InvoiceManager (InvoiceManager.exe on Windows).

3. Packaging Assets and PyInstaller sys._MEIPASS

Lila's lila.core.config resolves read-only assets through get_base_path() (honoring sys._MEIPASS when frozen) and writable files (SQLite database, cache, logs) through get_data_path(). In a frozen build the writable location is the OS application-data directory (%LOCALAPPDATA%\\<title> on Windows, ~/Library/Application Support/<title> on macOS, $XDG_DATA_HOME/<title> on Linux), not the read-only executable folder. On a frozen build, Lila looks for .env in that application-data directory first (then the current working directory) and keeps the SQLite database, cache and logs there. Keep DB_NAME relative (DB_NAME="lila") so it resolves under that directory.

Installers: .dmg and .msi

lila desktop build --installer auto --version 1.4.0 --publisher "Acme" --bundle-id com.acme.invoices
# macOS   -> dist/Invoices.app + dist/Invoices.dmg   (hdiutil, drag to Applications)
# Windows -> dist/Invoices.exe + dist/Invoices.msi   (WiX Toolset: dotnet tool install --global wix)

Each installer is built on its own OS. The MSI installs into Program Files, adds Start-menu and desktop shortcuts with the app icon, shows the icon in "Apps & features" and upgrades previous versions in place (the upgrade code comes from --bundle-id). If WiX is not installed the generated build/installer/<name>.wxs is kept with the command to run. The icon is --icon, else public/icon.ico|icns|png, public/favicon.ico or the Lila logo; PNG files are converted to ICO/ICNS when Pillow is installed.

4. Web-only and desktop-only routes

One codebase can be a website and a desktop app. Features that only make sense on the web (payments, uploads, webhooks, OAuth callbacks) can be left out of the desktop build, and desktop-only features out of the website. Removed routes do not exist in that mode (404), are not listed in /openapi.json, and React <Link> hides links to them. 

@router.post("/checkout", desktop=False)       # web only
billing = Router(prefix="/billing", desktop=False)  # whole group web only
@router.get("/local-backup", desktop="only")     # desktop app only
# .env (patterns: path + children, globs, route names)
DESKTOP_EXCLUDE=/payments,/api/*/upload,name:stripe_webhook

lila desktop routes                          # preview + web-only suggestions
lila desktop dev --exclude "/upload*"
lila desktop build --exclude "/payments" --auto-exclude   # baked into the executable

--auto-exclude adds the routes Lila detects as web-only (payments, checkout, billing, upload, webhook, OAuth...). Jinja templates get is_desktop() and route_available(path); React gets useLila().desktop, isAvailable(href), <WebOnly> and <DesktopOnly>. When the project uses Vite, lila desktop build runs lila react build first (--no-react to skip) and bundles public/build and app/locales.

Code signing and in-app updates

Unsigned apps are blocked by Gatekeeper and flagged by SmartScreen. Sign during the build:

# macOS: Developer ID + notarization (xcrun notarytool store-credentials lila-notary)
lila desktop build --installer dmg --sign-identity "Developer ID Application: Acme (TEAMID)" \
  --notary-profile lila-notary

# Windows: .pfx (password only via env) or a certificate thumbprint
set WINDOWS_SIGN_PASSWORD=...
lila desktop build --installer msi --sign-cert certs\\acme.pfx

Updates: build with --update-url https://downloads.example.com/app/latest.json, upload the installers and run lila desktop release --version 1.4.0 --base-url https://downloads.example.com/app (SHA-256 manifest; Windows and macOS entries are merged). In React, useDesktopUpdate() shows available/version/notes and install() downloads, verifies and opens the new installer.

import { desktop, useDesktopUpdate } from "@lila/desktop";
const update = useDesktopUpdate();
{update.available && <Button onClick={update.install}>Update to {update.version}</Button>}
await desktop.notify("Backup finished", "3 files");

5. Native Menu Bar, About, Preferences & Markdown Manual

By default, lila desktop dev and lila desktop build mount a native menu bar (File, Edit, View, Help, plus the macOS app menu) localized from LANG_DEFAULT / DESKTOP_MENU_LANG (en, es, pt, zh).

  • File: Preferences (opens a built-in Theme / Zoom / Data Folder modal, or navigates to DESKTOP_PREFERENCES_URL) and Quit.
  • Edit: Undo, Redo, Cut, Copy, Paste (works with React controlled inputs too) and Select All.
  • View: Back, Forward, Reload, Zoom In/Out/Reset and Fullscreen.
  • Help: Manual / Help opens an interactive Markdown modal (reads resources/manual.md by default, empty until edited; users can view and edit in-app unless --no-help-editable / DESKTOP_HELP_EDITABLE=False), Check for Updates (when --update-url is set) and About.
# Disable the native menu or lock manual editing in production:
lila desktop build --no-menu
lila desktop build --help-file resources/manual.md --no-help-editable --about "Desktop Client"

# Or call/override from JS/React (@lila/desktop):
# desktop.openHelp(), desktop.openPreferences(), desktop.openAbout()
# Intercept defaults with window.addEventListener("lila:desktop-help", e => { e.preventDefault(); ... })

Define extra_menus(window_getter, config) or get_menu(window_getter, defaults, config) in app/desktop_menu.py to add custom native menu items.
