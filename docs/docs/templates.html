Template Rendering (Jinja2)

In Lila, you can use Jinja2 to render HTML with server data

Jinja2 is the default for rendering HTML templates. You can pass data like translations, values, lists, or dictionaries using the context parameter.

Basic Usage in Routes

Render function 

from lila.core.templates import render
from lila.core.responses import Response
from lila.core.routing import Router
from lila.core.request import Request

router = Router()

@router.get("/")
async def home(request: Request):
    """Home page"""
    
    context = {
        "title": "Lila Framework",
        "message": "Hello from Lila!"
    }
    response = render(
        request, 
        "index.html", # HTML template name in resources/html/
        context=context
    )
    # Renders the 'index' template
    
    return response

routes=router.get_routes()

The render Function

The render function is located in lila.core.templates:

Template 

def render(
    request: Request,
    template_name: str | None = None,
    context: dict | None = None,
    extension: str = "jinja",
    csrf: bool = False,
    status_code: int = 200,
    template: str | None = None,      # alias for template_name
    layout: str | None = None,
    headers: dict | None = None,
    lang_default: str | None = None,
    files_translate: list | None = None,   # accepted for v1 compatibility
) -> HTMLResponse: ...

# render_markdown is also available:
def render_markdown(request, markdown_path, context=None, css_files=None, js_files=None): ...

Parameter Description

  • request:

    The Request object.

  • template_name (str):

    Template name. .jinja is preferred, but legacy .html names are accepted ("index.html" also finds index.jinja). With no extension, .jinja is used.

  • context (dict):

    Data to pass to the template (dictionaries, lists, etc.). It is merged over the base context.

  • csrf (bool):

    Accepted for readability. A CSRF token, the signed _csrf cookie and csrf_input are produced on every render.

  • status_code / headers / layout:

    Response status (default 200), extra response headers, and a layout override for the layout context variable.

  • files_translate (list):

    Deprecated v1 parameter. It is accepted but ignored: v2 locale files are flat JSON merged by language (app/locales/{lang}.json).

  • lang_default (str):

    Forced default language (ideal for SEO in routes like /es, /en, etc.).

In Lila, you can also use translate to pass translations to Jinja2, and parameters like title or version (ideal for structuring APIs: "v1", "v2").

Base Context Injection

All optimization features work thanks to the base context automatically injected into Jinja2 templates:

Base Context 

def get_base_context(request, lang_default=None, files_translate=None):
    # Values are resolved from .env / ConfigLoader and the request.
    return {
        "request": request,
        "title": ENV_CONFIG.get("TITLE_PROJECT", "Lila Application"),
        "description": ENV_CONFIG.get("DESCRIPTION_PROJECT", ...),
        "keywords": ENV_CONFIG.get("KEYWORDS_DEFAULT", ""),
        "author": ENV_CONFIG.get("AUTHOR_DEFAULT", ""),
        "version": ENV_CONFIG.get("VERSION_PROJECT", "2.0.0"),
        "lang": current_lang,
        "translate": Translate.get_dict(current_lang),
        "t": lambda key, default=None: Translate.t(key, lang=current_lang, default=default),
        "app_url": app_url,
        "debug": is_debug(),
        "debug_html": is_debug(),
        "layout": DEFAULT_LAYOUT,      # "lila/base.jinja"
        "csrf_token": "",
    }

# render() then adds: csrf_token, csrf_input and (when @seo was used) "seo".

Jinja2 Helpers

Lila registers these helpers as Jinja2 globals:

  • public(path):

    Resolves an asset under public/ to a URL, applies the lila optimize manifest (for example app.js → app.min.js, photo.png → photo.webp) and appends ?v=<mtime> for cache busting. When APP_URL is set and DEBUG is off, the URL is absolute.

  • asset(path):

    Returns a ready-to-use tag: a <link rel="stylesheet"> for .css, a <script src="..."> for .js, or the resolved URL otherwise. It does not load fonts or other files implicitly.

  • t(key, default=None) / translate:

    Current-language translation function and dictionary (translate['login']).

  • oauth_buttons():

    Renders the Google/GitHub/Discord buttons for the configured providers. Use {{ oauth_buttons() | safe }}.

Usage Example 
<!DOCTYPE html>
<html>
<head>
  <title>{{ title }}</title>
  <!-- Load Tailwind CSS v4 browser runtime and theme variables -->
  {{ asset('js/tailwind.js') | safe }}
</head>
<body>
  <h1>Welcome to Lila!</h1>
  
  <!-- Load javascript -->
  <script src="{{ public('js/main.js') }}"></script>
</body>
</html>

CSRF Protection in Templates

Every render() generates a signed CSRF token, sets the _csrf cookie and injects csrf_token, csrf_input into the template context. Passing csrf=True is accepted for readability; it does not change the token generation.

  • render(request, template, csrf=True):

    Produces csrf_token in the context and the signed _csrf cookie on the response.

  • csrf_input:

    Ready-made hidden input: <input type="hidden" name="_csrf" id="csrf" value="TOKEN" />. Use it with the | safe filter. The base context also includes the request object, so templates can access request data.

  • meta tag:

    The bundled lila/tailwind.jinja partial prints <meta name="csrf-token" content="{{ csrf_token }}">, which the client Http() helper reads automatically.

Route (Python) 

from lila.core.templates import render
from lila.core.middleware import csrf

@router.get('/contact')
async def contact_page(request: Request):
    return render(request, 'contact', csrf=True)

@router.post('/contact')
@csrf
async def contact_submit(request: Request):
    return JSONResponse({"success": True})
Template (Jinja2) 

<form method="POST" action="/contact">
  {{ csrf_input | safe }}
  <input type="text" name="name" />
  <button type="submit">Send</button>
</form>

The Http() helper in public/js/lila-client.js reads <meta name="csrf-token"> (or the #csrf input) and sends the value as the X-CSRF-Token header on every fetch. No additional client-side code is needed.

Lila CSS Utility Components

The bundled Tailwind setup includes a set of pre-configured utility classes that support dark mode natively. They are loaded by the layout's Tailwind Play CDN script (development) or by your precompiled CSS in production:

  • .card

    A beautiful, fully-responsive Material Design container card with light/dark border coloring, rounded-2xl padding, and smooth transition shadows.

  • .text-lila

    A premium, high-impact gradient title class styling using Lila's custom primary/secondary colors. Ideal for hero headers!

  • .input-lila

    A state-of-the-art interactive input class with elegant borders, dynamic focus ring effects, light/dark text support, and a smooth cursor placeholder transition.

  • .link-lila

    A gorgeous navigational anchor link styling with custom primary color transitions and sleek animated underlines.

  • .btn-primary / .btn-secondary / .btn-outline

    Pre-configured button styles featuring smooth translate-y hover elevations, beautiful color variations, and integrated loading/icon layout alignment.

Performance Notes

Templates are rendered by a single Jinja2 environment (auto-reload only in debug). Under lila dev, Jinja auto-reload is enabled and the SSE watcher reloads the browser and clears the locale/asset caches after template, locale or static edits. Some honest details:

  • Request state: @seo metadata is stored on request.state.seo and merged into the context, so a handler does not recompute it.
  • Translation caching: locale dictionaries are loaded once per language and kept in memory (SafeTranslationDict); the dev watcher clears that cache on edit.
  • No HTML minification: Lila does not minify rendered HTML. Use lila optimize for JS/CSS/images and the gzip=True App option (or your reverse proxy) for transport compression.
