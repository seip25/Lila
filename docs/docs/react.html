React with Vite (lila react)

Lila serves React pages built with Vite. Node.js is only needed while developing and building: production servers and desktop executables serve the hashed files in public/build. Title, description, Open Graph, canonical, robots and JSON-LD are rendered by Python on every page.

1. Setup

lila react init --install   # TypeScript (.tsx, strict tsconfig); --js for .jsx
lila react dev              # Vite (HMR, React Fast Refresh) + Lila dev server
lila react build            # public/build + .vite/manifest.json
lila react types            # resources/react/types/lila.ts from Pydantic schemas + models
lila react status           # dev / build / missing

2. Pages with server props

from lila.core.react import react_render

@router.get("/users/{id:int}")
async def user(request: Request, id: int):
    user = await User.get_by_id_async(id)
    return react_render(
        request, "Users/Show", {"user": user},
        title=user["name"], description="Profile", canonical=True,
        jsonld={"@context": "https://schema.org", "@type": "Person", "name": user["name"]},
        meta={"theme-color": "#1a73e8"},
    )
// resources/react/pages/Users/Show.tsx
import { Link } from "@lila";
import type { User } from "@/types/lila";   // generated by `lila react types`

export default function Show({ user }: { user: User }) {
  return <><h1>{user.name}</h1><Link href="/users">Back</Link></>;
}

<Link> and visit(url) request the next page with X-Lila-React: 1; the server answers with the component, props and head as JSON, the client swaps them and updates <title>, meta tags and JSON-LD. Back/forward work, non-React pages load normally and a new deploy (different asset version) triggers a full reload. http(url, {method, body}) sends the CSRF token. Props are visible in the page source: never pass secrets.

Forms and translations

import { useForm, useT } from "@lila";

export default function Login() {
  const t = useT();                                  // react_render(..., translations=True)
  const form = useForm({ email: "", password: "" });
  return (
    <form onSubmit={form.handleSubmit("/login", { redirect: "/dashboard" })}>
      <input type="email" {...form.field("email")} /> {form.errors.email}
      <input type="password" {...form.field("password")} /> {form.errors.password}
      {form.errors._form}
      <button disabled={form.processing}>{t("sign_in", "Sign In")}</button>
    </form>
  );
}

useForm sends JSON with the CSRF token, maps Lila's 422 errors ([{"field": "message"}]) to errors.field and other failures to errors._form. lila auth --react generates login, register, forgot/reset password, dashboard and profile pages built this way, on the same secure endpoints (throttles, lockouts, Argon2) as the Jinja version.

UI kit

lila react init copies the kit into resources/react/components/ui: it is your code, styled with Lila's palette and classes (.btn-*, .card, .form-control) and the same dark mode as the Jinja pages. Existing projects: lila react ui. 

import { Button, Card, DataTable, Form, Input, SubmitButton, Toaster, toast } from "@/components/ui";

<Form action="/api/products" initial={{ name: "", price: 0 }} successToast reset>
  <Input name="name" label="Name" required />          {/* 422 errors appear here */}
  <Input name="price" type="number" label="Price" />
  <SubmitButton>Save</SubmitButton>
</Form>

<DataTable url="/api/products" columns={[{ key: "name", label: "Name", sortable: true }]}
  onEdit="/products/:id" onDelete="/api/products/:id" />   {/* paginate_async() compatible */}

<Button variant="danger" url="/api/cache" method="DELETE" confirm="Clear?" successMessage>Clear</Button>

Also: Card, Badge, Modal, Drawer, Carousel, Toaster/toast, ThemeToggle, Spinner, Skeleton, PageSkeleton, ProgressBar, Select, Textarea, Checkbox.

3. SPA with React Router

router.spa("/app", meta={
    "*": {"title": "App", "description": "My app"},
    "login": {"title": "Sign in", "robots": "noindex"},
    "users/:id": lambda request, params: {"title": f"User {params['id']}"},
    "docs/*": {"title": "Docs"},
}, auth=False)

Every URL under /app returns the shell with the meta of the best match (static segments beat :params, which beat *). Values can be sync or async callables and may also return props and status. In the client, useLilaHead(useLocation().pathname) refreshes the head on navigation. The SPA catch-all is always matched after your API routes and static files. 

import { RouterProvider } from "react-router";
import { createLilaSpa } from "@lila";
import { AuthProvider, RequireAuth } from "@lila/auth";
import { createRouter, page } from "@lila/router";

const router = createRouter([{ element: <AppLayout />, children: [
  { index: true, element: <Home /> },
  { path: "admin", element: <RequireAuth roles={["admin"]} page redirectTo="/login" />,
    children: [{ index: true, lazy: page(() => import("./spa/Admin")) }] },
]}]);

createLilaSpa(() => <AuthProvider><RouterProvider router={router} /></AuthProvider>);

AuthProvider reads GET /api/auth/me (added by lila auth); useAuth() exposes user, login, logout and hasRole. Guards only decide what to render: keep auth=True / roles=[...] on the API routes.

4. Dev and production

The Lila Vite plugin writes public/build/hot while Vite runs; with DEBUG=True pages then load scripts from the dev server. Without it (or with DEBUG=False) Lila reads public/build/.vite/manifest.json and emits CSS, modulepreload and module script tags. A missing build returns a 500 with instructions and is reported by lila doctor. Jinja pages can embed Vite entries with {{ vite("resources/react/islands.jsx") }}.

Real-time and desktop hooks

@lila/realtime (useSSE, useWebSocket) connects to Channel streams and WebSocketHub; @lila/desktop exposes the native bridge (dialogs, notifications, updates, plus openBugReport, sendBugReport, getReportSettings, setTelemetryOptIn and sendTelemetryNow) as no-ops on the web — see Desktop. Start a project with everything wired: lila init -t full. CRUD pages: lila crud -m Product --react; admin: lila admin --react.
