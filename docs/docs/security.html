Roles, Permissions, API Keys & Refresh Tokens

1. Roles and permissions

Python 
from lila.core.permissions import define_roles, require_role, require_permission

define_roles({
    "admin": ["*"],
    "editor": ["posts.*", "comments.moderate"],
    "user": ["posts.read"],
})

@router.get("/api/stats", roles=["admin"])                    # any of these roles
async def stats(request): ...

@router.delete("/api/posts/{id:int}", permissions=["posts.delete"])   # all of these permissions
async def delete_post(request, id: int): ...

@router.get("/reports")
@require_permission("reports.view")                            # decorator form
async def reports(request): ...
  • Roles come from the session user: put "role": "editor" or "roles": [...] in Session.set at login.
  • To read roles from the database instead: set_role_loader(async def loader(request, user): return [...]) (cache it if it hits the DB).
  • Wildcards: * (everything) and prefix.*.
  • Not signed in → 401 for APIs / redirect to /login for pages; signed in without permission → 403.
  • API key scopes count as permissions too.
Jinja 
{% if can("posts.edit") %}<a href="/posts/{{ post.id }}/edit">Edit</a>{% endif %}
{% if has_role("admin") %}<a href="/admin">Admin</a>{% endif %}

2. API keys per user

Python 
# app/models/api_keys.py — so `lila migrate` creates the api_keys table
from lila.core.api_keys import ApiKey  # noqa: F401

from lila.core.api_keys import ApiKeys

token, key = await ApiKeys.create_async(user_id=7, name="CI", scopes=["posts.read"], expires_days=90)
# show `token` ONCE: lila_1a2b3c4d_...  (only its SHA-256 is stored)

keys = await ApiKeys.list_async(user_id=7)           # never includes the secret or its hash
await ApiKeys.revoke_async(key["id"], user_id=7)     # effective immediately

@router.get("/api/posts", api_key=True)              # any valid key
@router.post("/api/posts", api_key=["posts.write"])  # key must have the scope
async def posts(request):
    request.state.user        # {"id": 7, "scopes": [...], "via": "api_key"}

Clients send Authorization: Bearer lila_... or X-API-Key: lila_.... Expired or revoked keys get 401, missing scopes 403.

3. JWT access + refresh tokens

Python 
from lila.core.auth import JWT

pair = JWT.issue_pair({"user_id": user.id}, access_minutes=15, refresh_days=30)
# {"access_token": "...", "refresh_token": "...", "token_type": "bearer", "expires_in": 900}

@router.post("/api/token/refresh")
async def refresh(request: Request):
    body = await request.json()
    new_pair = await JWT.refresh_async(body.get("refresh_token", ""))
    if not new_pair:
        return JSONResponse({"success": False, "message": "Invalid refresh token"}, status_code=401)
    return new_pair

JWT.revoke(refresh_token)       # logout this device (whole token family)
JWT.revoke_user(user.id)        # "log out everywhere" / after a password change
  • Each refresh token works once and is rotated. Re-using an old one (a stolen copy) revokes the whole family.
  • Refresh state (token id, family, expiry) lives in app/data/lila_system.db: shared by workers and kept across restarts; the tokens themselves are never stored.
  • @validate_token accepts access tokens only; a refresh token gets 401.
